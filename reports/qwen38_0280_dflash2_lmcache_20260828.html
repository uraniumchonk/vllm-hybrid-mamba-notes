Why LMCache

vLLM GPU prefix cache dies when the engine restarts or the KV pool evicts. LMCache keeps the same hashed chunks in RAM (L1) and on a big disk (L2). Next request with the same system/tool prefix does a retrieve instead of a full prefill.

  • Reuse: agent system+tool prefix is 20–28k tokens. After the first store, later turns pull it back in 6–9 ms (Retrieved 25600 tokens in 0.007s). During the second MeowChat soak, read/write token ratio was ~74:1.
  • Disk is cheap: L2 sits on a 1.5 TB NVMe pool. That soak grew L2 to ~22 GB without touching GPU KV capacity. Prefixes survive engine restarts; wipe L2 only when the hash geometry changes (block size / dtype).

0.28.0 silently replaces LMCacheMPConnector with OffloadingConnector if you also pass --kv-offloading-*. Do not combine them.
