The gain shows up on every type and both concurrency levels. It is not a prefill artifact: the ITL tail shrinks (smoother streaming) and aggregate throughput rises in lockstep with single-stream decode.

Why: the allreduce transport switched

TP2 needs an allreduce every layer. Consumer GeForce cards are blocked from peer access by the stock driver, so NCCL stages through host memory (SMH): GPU→CPU→GPU over PCIe. This box enables real P2P with a patched open kernel module; when that module is active, vLLM's CUSTOM allreduce rides PCIe P2P instead.

How to lose P2P without noticing

On this box the trap is a kernel upgrade: dkms rebuilds the stock module for the new kernel into updates/dkms/, which outranks the patched open module (installed under kernel/drivers/video/). The next boot loads the stock module, NVreg_EnableGpuFirmware=0 takes effect (GSP off), and peer access silently disappears — no error, vLLM just falls back to PYNCCL. Symptom checks:

journalctl -b 0 | grep "loading NVIDIA"     # "Open Kernel Module" vs plain
nvidia-smi -q | grep "GSP Firmware"          # N/A = GSP off
~/card/p2p_check_new 0 1                     # canAccessPeer matrix + GB/s
curl -s .../logs/stream/qwen-27b-default | grep "all-reduce"   # PYNCCL-only = staging
