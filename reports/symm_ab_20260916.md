# NCCL_SYMM_MEM A/B 實驗報告（2026-09-16）

## 背景
- 4× RTX 3090（sm86）經 PEX 交換器全 P2P（~25GB/s）、無 NVLink。
- vLLM 對 >2 張 PCIe GPU **自動停用** custom allreduce（設計限制，見 `custom_all_reduce.py:179`；且 `should_custom_ar()` 註解明言 4+ 非 NVLink 卡「little performance improvement」）。
- vLLM 內建替代路徑 **NCCL_SYMM_MEM**（`min_world_size=4`；官方 tuning：≤16KiB 小訊息延遲低於 custom、≥512KiB 頻寬更好）——**預設關閉**（`VLLM_USE_NCCL_SYMM_MEM=0`）。
- 動機：decode 時 allreduce 訊息 ≈ 10KiB（5120 × bf16）落在 symm_mem 強項區間，期望改善 n1（單串流）延遲。

## 環境與設定
- 對象：default lane（INT8 W8A16 TP4 + DFlash2 spec W8/K7 + LMCache + block 1600 + 262144 ctx + kv 8.85e9）
- 開關：`VLLM_USE_NCCL_SYMM_MEM=1`（env，僅 default lane）
- 驗證：`Using ['NCCL_SYMM_MEM', 'PYNCCL'] all-reduce backends` ✓（開前：`['PYNCCL']`）
  - 註：torch 版 SYMM_MEM 不支援 sm86（`SymmMemCommunicator: Device capability 8.6 not supported`），NCCL 版才啟用成功。

## 正確性（PASS）
- 固定題組 ×5（math/code/prose/longctx/chitchat，temp0/seed42、順序發送）：
  - **math 721 字逐字相同**；longctx 相同；code 95.8%、chitchat 98.3%、prose 72.5%（近似平手 token 分支）。
  - **同實例重跑 5/5 完全一致** → 差異確實來自 symm 數值改變（非雜訊）；分歧內容目檢皆為等價寫法/風格分支，無劣化。
- spec acceptance rate：symm 0.3240 vs no 0.3237（無差異）。

## 效能 A/B（suite 對 suite，單跑）
| 區塊 | 結果 |
|---|---|
| typev2 n1 dec | +4% / +3% / -1% / -8% / -0% / +10%（numeric/code/prose/mixed/realjob/chitchat）→ 平均 ≈ +1%，雜訊級 |
| typev2 n4/n8 | 正負亂跳：realjob n8 +11%、chitchat n4 **-42%**、code n8 -17%… |
| ctx | ctx64k n1 +25% vs ctx32k n1 **-41%**（同類負載反向大跳 = 雜訊） |
| conc | n1 -15%、n4 +0%、n8 -3% |
| prefix | 2.90x vs 2.88x（相同） |

**結論：無可辨識的系統性增益，全部落在單跑雜訊內。** 未救到 n1，亦無明確損害。

## 裁決
- **撤除**（回上游預設 `['PYNCCL']`）。理由：無實測增益 + 上游對 sm86/PCIe 為未標測領域 + 維持棧乾淨。
- 若未來要再追：需 `--repeats≥3` 的多輪統計版本才壓得住雜訊；開關是一行 env、隨時可重開。
